# 全网页端架构决策

> 状态：已生效
>
> 生效日期：2026-07-27
>
> 决策编号：ADR-WEB-001

## 1. 决策

化妆部预约系统统一采用响应式网页，不再建设或发布微信小程序。

| 角色 | 主要设备 | 当前客户端 |
|---|---|---|
| 主播 | 手机 | React 响应式网页 |
| 运营 | 手机 | React 响应式网页 |
| 化妆师 | 手机 | React 响应式网页 |
| 客服 | 电脑 | React 管理后台 |
| 管理员 | 电脑 | React 管理后台 |

手机端和电脑端位于同一个 `apps/admin-web` 工程，共享组件、API 客户端、认证会话和业务类型；页面按角色和视口提供不同导航与布局。服务端仍做最终权限校验，不能依赖前端隐藏入口。

## 2. 当前技术结构

- 前端：React、TypeScript、Vite、React Router、响应式 CSS。
- API：NestJS 模块化单体。
- 数据库：PostgreSQL、Prisma、事务和数据库约束。
- 缓存与任务：Redis、独立 Worker。
- 测试：Vitest、Nest 测试、Playwright、数据库和并发检查脚本。
- 部署：网页静态资源、API、Worker、PostgreSQL 和 Redis；生产入口使用 HTTPS。

## 3. 认证与账号

- 五类人员都使用系统账号和密码登录。
- 首次登录使用管理员或客服设置的临时密码，系统要求立即修改。
- 同一账号拥有多个有效角色时，登录后选择本次使用的角色。
- 密码重置会撤销现有会话；登录失败次数、锁定、会话刷新和角色权限由服务端处理。
- 管理员可维护全部账号；客服只能在本人场地和授权范围内维护账号。

项目不再使用微信 OpenID、`wx.login`、AppID、AppSecret、一次性绑定码或绑定挑战。

## 4. 已删除范围

- `apps/miniapp` 及其 Taro 构建配置、依赖和脚本。
- 微信登录 API、适配器、配置和测试。
- 一次性绑定码、绑定挑战的 API、服务、页面和测试。
- 数据库表 `account_binding_codes`、`auth_binding_challenges` 及其关联。
- 小程序发布、微信开发者工具冒烟和微信域名配置要求。

空的本地 `apps/miniapp` 文件夹若被微信开发者工具占用，关闭工具后即可删除；它不属于 Git，也不参与构建或部署。

## 5. 保持不变的内容

预约、固定、班次、工作日、加班、请假、临时不可排班、零点锁定、场地隔离、每日次数、并发占位、审计和历史排班等业务规则不因客户端迁移而改变。API 和数据库继续作为唯一业务事实来源。

## 6. 文档解释规则

本决策替代其他文档中关于“小程序、Taro、微信登录、绑定码、微信开发者工具和小程序发布”的旧渠道说明。其他文档中的业务规则、权限范围、字段、状态和数据库约束继续有效。

[上线前全量验收记录](上线前全量验收记录.md)保留旧小程序阶段的真实历史证据，但不能用来证明当前网页端已经完成真机验收。当前迁移验证见[全网页端迁移验收记录](全网页端迁移验收记录.md)。
