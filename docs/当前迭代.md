## 1. 当前目标

在保留微信登录和一次性绑定的前提下，完成主播、运营和化妆师在小程序内的排班查看与业务操作。

- 微信订阅消息、公众号消息或短信。

所有业务结果和变化以数据库事实、审计记录和小程序实时查询为准。

## 4. 已确认决策

| Excel 导出 | 客服按场地；管理员支持分场地或合并 |

仍待上线前决定：生产云、域名、备案主体和最终部署规模。

## 5. 当前技术风险

- 小程序排班查询、普通预约、取消、改期和化妆师首次班次已接入真实 API；请假、班次后续修改、加班和固定关系入口仍待逐项实现。
- PostgreSQL 和 Redis 统一使用 UTC，应用代码不依赖进程本地时区；业务日期和展示时间继续固定为 `Asia/Shanghai`。旧的本地开发数据库需在用户确认后安全重建，避免保留非 UTC 测试时间。
- Taro 的部分开发期间接依赖仍有上游未修复的审计项；生产依赖高危门禁当前通过。
- 仓库尚未配置 GitHub 远程地址，因此只有本地等价 CI 记录。

## 7. 本阶段退出标准

- 小程序不出现订阅消息、通知模板、提醒或发送状态入口。
- 微信登录、会话刷新、首次绑定和角色选择保持可用。
- 请假主体必须由服务端当前身份确定，客户端不能代替他人请假。
- 日期范围、重复请假、撤销截止线和行版本由服务端重新校验。
- 请假创建与受影响预约取消必须原子成功或原子失败。
- 页面具备影响确认、重复提交保护、错误反馈和成功刷新状态。
- 格式、静态检查、类型检查、测试、构建、数据库检查、端到端和安全门禁全部通过。
