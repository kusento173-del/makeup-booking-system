## 2. 第一阶段现行范围

已包含：

- 微信登录、一次性绑定、会话刷新和多角色账号。
- 普通预约、第二次确认、取消、改期、换化妆师和每日最多两次。
- 固定关系新建、变更、取消、审批、未来生成和三端可见性。
- 化妆师班次、工作日、请假、加班和临时不可排班。
- 主播请假及受影响预约取消。
- 今日、明日、未来七日和历史排班。
- 客服按场地操作、管理员全局操作、审计记录和 Excel 导出。
- 人员主数据、主播—运营关系和一次性绑定码管理。

明确不包含：

- 讲师角色。
- 微信订阅消息、公众号消息、短信和站内消息中心。
- 历史固定主播 Excel 自动导入。
- 自动排班；预约人选择空闲档期，系统负责冲突控制。

## 3. 当前唯一主任务

任务编号：`M9-PRODUCTION-01`

取得生产资源后执行：

1. 确认云服务器或容器平台、CPU、内存、磁盘和网络规格。
2. 配置正式域名、备案、TLS 证书和微信小程序合法请求域名。
3. 配置生产 PostgreSQL、Redis、持久化存储和独立备份位置。
4. 生成全新的生产密钥并运行 `pnpm deploy:check`。
5. 使用 Git 提交号构建不可变镜像，先执行迁移和备份，再启动服务。
6. 导入上线当天的最新名单并核对人数、场地、重名主播和未匹配运营关系。
7. 在目标服务器复跑 600 并发、备份恢复、权限矩阵和真实手机验收。
8. 接入外部健康监控、日志告警和明确的告警接收人。
9. 客服、管理员、两地运营、主播和化妆师完成正式 UAT 确认。

## 4. 继续开发规则

- 新任务先阅读本文件，再按链接进入对应专项文档；不需要把全部文档一次性载入上下文。
- 每个完整改动必须更新相关文档、通过对应门禁并创建一次 Git 提交。
- `apps/miniapp/project.config.json` 是用户本地微信开发者工具配置，不随普通代码提交。
- 发现新缺陷先记录到 [上线前全量验收记录](上线前全量验收记录.md)，修复并回归后再提交。
- 第一阶段范围如发生变化，先更新产品需求、规则和验收标准，再修改代码。
