# 上线评估与剩余风险

> 2026-07-27 状态更新：本文件记录的生产候选结论基于原“小程序＋管理后台”终端。五类角色统一网页的架构变更已经进入 `M10-WEB-01`，在功能对等、认证迁移和重新验收完成前，原生产候选结论暂停生效。

## 1. 评估结论

截至 2026-07-26，原终端方案代码达到“生产候选版本”标准：

- 测试范围内没有已知未修复的业务代码阻断项。
- 五类角色权限、核心业务闭环、数据库约束、并发抢占、长稳性能、安全、备份恢复和生产容器均已通过验收。
- 当前结论是“原业务与基础设施基线已验证”；全网页端变更完成前不是可上线版本。

正式上线仍受第 3 章外部阻断项约束。任何软件都无法证明绝对没有潜在缺陷；本结论表示已对当前需求、代码和可控环境进行了系统性验证，并记录了尚不能由本机测试消除的风险。

## 2. 已关闭的高风险缺陷

| 范围 | 已关闭问题 | 验证结果 |
|---|---|---|
| 预约并发 | 同一档期重复占用、每日次数和原子改期 | 100 路同档期仅 1 路成功；数据库无重叠 |
| 固定关系 | 规则日期重叠、请假撤销恢复、固定实例释放 | 业务、数据库约束和三端状态一致 |
| 会话 | 临时网络故障误删登录、Redis 断连导致 API 崩溃 | 会话保留；Redis 恢复无需重启 API |
| 权限 | 客服跨场地、运营越权、客户端参数伪造 | 401/403 与服务端范围限制通过 |
| 审计 | 有日志但客服和管理员无法查看 | 已增加按场地隔离的只读审计页面 |
| 数据恢复 | 审计函数导致标准恢复失败 | 642 MB 数据库完整恢复且关键表一致 |
| 部署 | 无生产镜像、TLS 网关、健康检查和备份入口 | 完整生产编排和故障恢复演练通过 |
| 代理安全 | 来源 IP 全变为网关或可伪造 | 单层可信代理与覆盖式转发头验证通过 |
| 网关静态站点 | 管理后台首页内部重定向循环 | HTTPS 首页与前端路由返回 200 |

完整缺陷根因和回归证据见 [上线前全量验收记录](上线前全量验收记录.md)。

## 3. 正式上线阻断项

以下项目未完成前，不应把系统开放给正式用户：

1. **生产基础设施未确定**
   - 尚未确定云厂商、部署区域、服务器或容器平台及最终规格。
   - 600 并发结论来自本地隔离环境，必须在最终生产规格上复跑。

2. **域名、备案和手机网页发布条件未完成**
   - 需要正式域名、可用 TLS 证书和符合部署地区要求的备案。
   - 需要完成手机网页在真实 iOS、Android、微信内浏览器和系统浏览器中的验收。

3. **生产 PostgreSQL 与 Redis 未配置**
   - 必须使用独立生产实例、TLS 连接、访问控制和持久化。
   - 必须在生产同等级实例上再次完成备份与隔离恢复演练。

4. **外部监控和告警接收人未确定**
   - 容器健康检查已经具备，但尚未接入外部可用性探测、日志告警和磁盘、数据库容量告警。
   - 必须明确至少两名告警接收人和故障升级路径。

5. **正式名单与账号尚未上线导入**
   - 需要使用上线当天最新主播、化妆师、运营和负责关系名单。
   - 75 条历史无法匹配关系必须继续留空并由人工核对，不能模糊匹配。
   - 需要创建正式客服、管理员账号并更换所有测试密钥和密码。

6. **业务 UAT 尚未确认**
   - 至少由两地客服、管理员、运营、主播和化妆师代表在真实手机和电脑完成关键路径验收。
   - 无锡场地正式启用前应单独完成场地级 UAT。

## 4. 可接受但需明确知晓的剩余风险

| 风险 | 当前影响 | 缓解措施 |
|---|---|---|
| Taro 构建链仍有上游依赖公告 | 仅在全网页迁移期间保留 | 功能对等后删除小程序、Taro 和相关依赖 |
| 第一阶段无主动消息通知 | 用户不会收到微信、短信或站内提醒，需要主动查看网页或由客服维持现有沟通 | 已按产品决策删除全部通知代码；上线培训中必须说明 |
| 当前生产编排默认单网关、单 API、单 Worker | 可自动重启但不是零停机，高可用依赖外部平台 | 首期可接受时需书面确认；高可用场景使用平台副本和负载均衡 |
| 本地 Docker Desktop 中文路径无法使用 Compose Bake | 影响本机组合构建，不影响直接构建和 Linux 部署 | 正式服务器使用 ASCII 路径和直接镜像构建 |
| 真实手机浏览器、机型和弱网覆盖有限 | 桌面浏览器响应式模式不能完全替代真机 | 至少覆盖 iOS、Android、微信内浏览器、系统浏览器、Wi-Fi 和移动网络 |
| 业务量长期超过当前预留规模 | 当前已验证 1,500 单/日、600 并发，不能无限外推 | 上线后监控 p95、连接池和数据库体积，达到阈值前扩容 |

## 5. 上线建议

- 当前冻结原渠道生产发布，先完成 `M10-WEB-01` 的网页迁移和重新验收。
- 首次开放建议按场地灰度：内部管理员与客服 → 少量运营和主播 → 单场地 → 全场地。
- 灰度期间每天核对预约数、取消数、档期冲突、错误率、p95 响应时间、数据库容量和备份结果。
- 上线前先做备份；数据库迁移和应用发布分开执行；失败时按 [部署与运维手册](部署与运维手册.md) 回滚。
- 若首期部署为单节点，应安排明确维护窗口并接受短时重启风险；若要求无感升级，应先改为平台化多副本部署。

## 6. 最终放行标准

只有同时满足以下条件才标记“允许正式上线”：

- 第 3 章六类阻断项全部关闭。
- 生产环境检查脚本、迁移、健康检查、备份和恢复全部通过。
- 目标环境 600 并发和关键业务回归通过。
- 正式账号、最新名单和场地权限核对通过。
- 业务负责人确认剩余风险并完成 UAT。
- 已记录可回滚的 Git 提交号、镜像标签、数据库备份和发布负责人。
