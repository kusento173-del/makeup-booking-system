# 单机服务器部署手册

> 适用范围：4 核 4 GB、40 GB SSD 的 Linux 轻量服务器，PostgreSQL、Redis、API、Worker 和网页全部运行在同一台服务器。
>
> 当前用途：备案完成前的受限试运行。公网 IP HTTPS 只解决传输加密，不替代 ICP 备案。

## 1. 部署结构

单机编排使用 `compose.single-server.yaml`：

- `gateway`：网页、HTTPS、API 反向代理和限流；
- `api`：业务接口；
- `worker`：固定预约生成、预约完成和导出任务；
- `postgres`：业务数据库，仅 Docker 内网可访问；
- `redis`：会话、限流和短期缓存，仅 Docker 内网可访问；
- `backup`：每日数据库逻辑备份，服务器本地保留 7 天；
- `migrate`：发布时单独执行数据库迁移。

容器内存上限合计约 2.8 GB，剩余内存供 Ubuntu、Docker 和短时峰值使用。服务器必须配置 Swap，但 Swap 只用于防止瞬时内存不足，不能替代物理内存。

## 2. 云防火墙

只开放以下端口：

| 端口 | 来源 | 用途 |
|---|---|---|
| 22 | 仅管理员当前公网 IP | SSH |
| 80 | 全部 IPv4 | IP 证书 HTTP-01 校验及跳转 HTTPS |
| 443 | 仅参与测试的办公或手机出口 IP | 试运行访问 |

不得开放 `3000`、`5432`、`6379` 或 Docker 管理端口。完成正式备案和验收后，才评估是否把 443 放开至全部用户。

## 3. 系统准备

使用 Ubuntu Server 22.04 LTS 64 位。安装 Docker Engine 与 Compose 插件后，创建 2 GB Swap：

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

确认资源：

```bash
free -h
df -h /
docker version
docker compose version
```

腾讯云中国大陆实例可将
`deploy/docker-daemon.tencent-cloud.json` 安装为 `/etc/docker/daemon.json`，
使用仅限腾讯云内网访问的镜像加速源。修改后执行：

```bash
sudo systemctl restart docker
docker info
```

项目建议放在 `/opt/makeup-booking`，并由专用非 root 运维账号管理。

## 4. 创建生产配置

代码上传到服务器后，在项目根目录执行以下命令。该命令只使用 Node 官方容器生成随机密钥，不要求宿主机安装 Node.js：

```bash
docker run --rm \
  -v "$PWD:/workspace" \
  -w /workspace \
  node:24.15.0-bookworm-slim \
  node scripts/create-single-server-environment.mjs \
  服务器公网IP 证书联系邮箱
```

随后校验：

```bash
docker run --rm \
  -v "$PWD:/workspace" \
  -w /workspace \
  node:24.15.0-bookworm-slim \
  node scripts/check-production-environment.mjs deploy/single-server.env

docker compose \
  --env-file deploy/single-server.env \
  -f compose.single-server.yaml \
  config --quiet
```

`deploy/single-server.env` 包含生产密钥，不得提交 Git、发送到聊天或工单。

镜像构建默认使用 npm 官方源。如果服务器到官方源持续超时，可以临时把
`NPM_REGISTRY` 改为可信的国内镜像；依赖仍按锁文件中的完整性摘要校验。构建成功后建议恢复官方源。

腾讯云中国大陆实例构建时还可在 `deploy/single-server.env` 中设置：

```dotenv
NPM_REGISTRY=https://registry.npmmirror.com
DEBIAN_MIRROR=http://mirrors.tencentyun.com/debian
DEBIAN_SECURITY_MIRROR=http://mirrors.tencentyun.com/debian-security
```

这些变量只影响镜像构建下载地址，不改变最终依赖版本。

## 5. 首次启动与 IP HTTPS

为申请第一张 IP 证书，先只启动 HTTP 网关：

```bash
export COMPOSE_PARALLEL_LIMIT=1
export GATEWAY_TARGET=gateway-http

docker compose \
  --env-file deploy/single-server.env \
  -f compose.single-server.yaml \
  build

docker compose \
  --env-file deploy/single-server.env \
  -f compose.single-server.yaml \
  --profile migration \
  run --rm migrate

docker compose \
  --env-file deploy/single-server.env \
  -f compose.single-server.yaml \
  up -d postgres redis api worker gateway
```

确认 `http://服务器公网IP/healthz` 返回 `ok`，然后申请并安装可信 IP 证书：

```bash
chmod +x deploy/manage-ip-certificate.sh deploy/single-server-maintenance.sh
./deploy/manage-ip-certificate.sh issue
```

成功后验证：

```bash
curl --fail https://服务器公网IP/healthz
curl --fail https://服务器公网IP/api/health
docker compose --env-file deploy/single-server.env -f compose.single-server.yaml ps
```

Let’s Encrypt IP 证书有效期约 160 小时，必须自动续期。每天检查两次：

```cron
17 */12 * * * cd /opt/makeup-booking && ./deploy/manage-ip-certificate.sh renew >> deploy/logs/certificate.log 2>&1
```

## 6. 40 GB 磁盘维护

本地只保留最近 7 天数据库备份，每日清理 7 天前未被运行容器使用的镜像和全部无用构建缓存。正在运行的版本不会被清理：

```cron
30 2 * * * cd /opt/makeup-booking && ./deploy/single-server-maintenance.sh >> deploy/logs/maintenance.log 2>&1
```

还必须在云平台开启系统盘自动快照，并把数据库备份定期复制到服务器之外。Docker 数据卷和同一块系统盘上的备份都不能抵御整台服务器或系统盘损坏。

磁盘使用率达到 80% 时停止继续发布，先检查：

```bash
df -h /
docker system df
docker compose --env-file deploy/single-server.env -f compose.single-server.yaml logs --since 24h
```

不要删除 `postgres-data`、`redis-data`、`backup-data` 或 `export-data` 数据卷。

## 7. 发布顺序

每次发布严格按以下顺序：

1. 执行并验证数据库备份；
2. 记录当前 Git 提交；
3. 顺序构建镜像，避免 4 GB 内存并行构建；
4. 单独执行迁移；
5. 更新 API、Worker 和 Gateway；
6. 检查健康状态、日志和磁盘；
7. 使用五种角色各完成一次登录与只读查询，再执行一条专用测试预约。

```bash
export COMPOSE_PARALLEL_LIMIT=1
./deploy/single-server-maintenance.sh
docker compose --env-file deploy/single-server.env -f compose.single-server.yaml build
docker compose --env-file deploy/single-server.env -f compose.single-server.yaml --profile migration run --rm migrate
docker compose --env-file deploy/single-server.env -f compose.single-server.yaml up -d
docker compose --env-file deploy/single-server.env -f compose.single-server.yaml ps
```

## 8. 上线后扩容条件

满足任一条件时将服务器升至 4 核 8 GB，或把 PostgreSQL、Redis 拆到托管服务：

- 连续 10 分钟内存超过 80%；
- 出现 OOM 或明显 Swap 持续读写；
- API 五分钟 `p95` 超过 2 秒；
- PostgreSQL 连接、锁等待或慢查询持续增长；
- 40 GB 磁盘长期超过 70%；
- 单机故障已无法接受。

服务器部署完成后仍需重新运行核心业务验收和 600 并发测试。本地测试结果不能替代目标服务器实测。

## 9. 本地编排验收记录

2026-07-29 已使用隔离项目名和临时数据卷完成以下验证，测试完成后临时容器、数据卷和镜像标签均已清理：

- 全仓格式、Lint、类型检查、467 项自动化测试和生产构建通过；
- HTTP 证书申请网关与 HTTPS 网关均实际启动，`/healthz` 返回正常；
- 单机 PostgreSQL、Redis、API、Worker 和 Gateway 全部健康；
- 43 个数据库迁移在全新 PostgreSQL 数据卷成功执行；
- `/api/health` 同时确认数据库和 Redis 正常；
- PostgreSQL 自定义格式备份创建并通过 `pg_restore --list` 校验；
- 空载容器内存约为 PostgreSQL 46 MB、Redis 6 MB、API 182 MB、Worker 36 MB、Gateway 67 MB。

该结果证明单机编排可以运行，不代表目标 4 核 4 GB 服务器已经完成容量验收。正式服务器部署后仍需复跑业务回归、备份恢复和 600 并发。
