## 3. 自动运维

服务器时区为 `Asia/Shanghai`，时间同步正常。

- 每天 `02:30`：生成并验证数据库备份，保留最近 7 天，并执行受控磁盘清理。
- 每 12 小时：检查公网 IP 短期证书续期；证书未变化时不重启网关。
- Docker 日志：每个服务最多 3 个文件，每个文件 10 MB。
- 当前系统盘使用率：迁移验收时为 35%。
- 当前可用内存：迁移验收时约 2.6 GB，另有 2 GB Swap。

数据库备份和 Docker 数据卷仍在同一块系统盘，不能替代云平台快照和异机备份。必须在腾讯云开启系统盘自动快照，并定期把数据库备份复制到服务器之外。

## 4. 旧服务器回滚边界

旧服务器的 Gateway、Worker 和 API 已停止，PostgreSQL、Redis、证书、环境配置和 Docker 数据卷暂时保留。建议至少保留 7 至 14 天，不删除服务器、不删除卷、不执行 `docker compose down --volumes`。

如新服务器出现阻断性故障：

1. 先停止新服务器 Gateway、Worker 和 API，避免两边同时写入。
2. 明确新服务器是否已经产生新业务数据；如有，先备份并决定回迁策略。
3. 在旧服务器 `/opt/makeup-booking` 恢复 API、Worker 和 Gateway。
4. 验证旧地址 HTTPS、API 健康和五角色登录后再通知用户切回。

不得直接同时启动两套生产写入服务，否则会形成两个独立数据库并产生数据分叉。
