### 4.2 已发现问题

#### QA-SEC-001：Excel 导出依赖链存在高危拒绝服务漏洞

- 严重级别：高，上线阻断。
- 发现方式：`pnpm security:check`
- 受影响链路：`exceljs -> archiver -> minimatch -> brace-expansion`
- 当前版本：仓库存在 `brace-expansion` 1.1.16、2.1.2、5.0.7。
- 安全版本：5.0.8。
- 修复：使用 pnpm 精确覆盖将所有受影响传递版本统一为 `brace-expansion 5.0.8`，未接受自动工具提出的其他 23 个无关跨版本覆盖。
- 回归：
  - `pnpm security:check` 通过，高危漏洞由 1 个降为 0 个；
  - 依赖树仅剩 `brace-expansion 5.0.8`；
  - Excel 导出 8 个测试文件、23 项测试全部通过；
  - ESLint、全仓类型检查、471 项测试及全部生产构建再次通过。
- 状态：已修复并通过回归。

#### QA-SEC-002：构建工具链仍报告中低危依赖

- 严重级别：中低，当前不是上线阻断。
- 数量：2 个低危、10 个中危。
- 范围：
  - Webpack、esbuild、webpack-dev-server 均来自 Taro 小程序构建/开发链，不进入 API、Worker 或小程序运行时；
  - Valibot 来自 Prisma 的可选开发链；
  - UUID 来自 ExcelJS，漏洞条件为调用 v3/v5/v6 且传入外部缓冲区；本系统不调用这些接口，Excel 导出回归已通过。
- 处置：暂不使用自动工具提出的跨大版本强制覆盖；保留在发布风险清单，后续优先随 Taro、Prisma 和 ExcelJS 官方依赖升级消除。
- 状态：已评估，持续跟踪。

#### QA-API-001：取消预约响应状态与 OpenAPI 契约不一致

- 严重级别：中。
- 发现方式：隔离数据库真实 HTTP 预约闭环。
- 现象：`POST /appointments/{id}/cancel` 的文档声明 `200 OK`，实际因 NestJS 默认行为返回 `201 Created`。
- 影响：不会导致当前前端失败，但“取消既有资源”并未创建资源，错误状态会影响严格客户端、接口监控和后续集成。
- 修复：为取消接口显式设置 `@HttpCode(200)`，并增加控制器元数据回归测试。
- 回归：
  - API 79 个测试文件、380 项测试通过；
  - API TypeScript 检查与生产构建通过；
  - 真实 HTTP 取消操作返回 `200`；
  - 预约闭环和 20 路抢档回归通过。
- 状态：已修复并通过回归。

#### QA-DB-001：取消化妆师请假时无法恢复原固定预约

- 严重级别：高，上线阻断。
- 发现方式：隔离数据库真实 HTTP 固定预约—请假—取消请假闭环。
- 现象：化妆师请假会正确取消当天固定预约，但取消尚未开始的请假时接口返回 `500`，原固定预约无法恢复。
- 根因：业务服务实现了恢复逻辑，但旧数据库历史保护触发器只允许预约从 `BOOKED` 变为 `CANCELLED/COMPLETED`，禁止由请假取消产生的 `CANCELLED -> BOOKED`；模拟数据库单元测试未覆盖该数据库触发器冲突。
- 修复：
  - 新增第 36 个数据库迁移，仅允许满足全部条件的固定预约恢复：取消原因为化妆师请假、来源请假记录已取消、固定规则仍存在、预约身份和时间不变、版本严格递增、取消及完成字段全部清空；
  - 普通已取消预约、单次预约、未取消的请假和其他历史字段仍不可恢复或篡改；
  - 增加数据库级回归夹具，直接验证该唯一合法反向状态迁移。
- 回归：
  - 请假与加班、临时不可排、预约历史三组数据库约束检查通过；
  - 真实 HTTP 取消请假返回 `204`，请假状态变为 `CANCELLED`，固定预约恢复为 `BOOKED`；
  - 隔离测试库删除重建后，36 个迁移从零应用成功；
  - 真实名单重新导入后，35 项角色/场地检查、16 项预约闭环及 21 项固定/请假闭环全部通过；
  - 20 路同时抢同一档期仍保持仅 1 路成功、19 路冲突。
- 状态：已修复并通过空库全链路回归。

#### QA-API-002：班次变更审批响应状态与 OpenAPI 契约不一致

- 严重级别：中。
- 发现方式：隔离数据库真实 HTTP 化妆师班次变更审批闭环。
- 现象：`POST /shift-changes/{id}/review` 已成功完成审批和创建新班次版本，但返回 `201 Created`，文档声明为 `200 OK`。
- 影响：严格按状态码判断的后台客户端会把成功审批识别成异常，用户可能重复操作。
- 修复：为审批接口显式设置 `@HttpCode(200)`，并增加控制器元数据回归测试。
- 回归：
  - API 79 个测试文件、381 项测试通过；
  - 真实 HTTP 班次审批返回 `200`，新班次版本号递增；
  - 静态扫描全部声明 `ApiOkResponse` 的 POST 控制器，未发现其他缺少显式成功状态码的接口；
  - 空库重建后的 104 项角色与业务 HTTP 断言全部通过。
- 状态：已修复并通过回归。

#### QA-FUNC-001：客服和管理员无法查看操作审计

- 严重级别：高，上线阻断。
- 发现方式：按产品需求核对客服/管理员后台及 API 路由。
- 原现象：关键业务已向不可修改的 `operation_logs` 写入完整审计，但系统没有审计查询 API，后台菜单也没有“操作记录”页面。
- 原影响：客服无法查看本站修改记录，管理员无法查看全部修改记录，不满足产品需求第 18 章及验收用例 `AUDIT-001`～`AUDIT-003`。
- 修复：
  - 增加只读分页查询 API，支持操作代码和对象类型筛选；
  - 客服查询条件由服务端强制限定为所属场地，不能通过参数读取其他场地；
  - 管理员可查看全局及各场地记录；
  - 后台“系统设置”增加“操作记录”页面，显示操作人、角色、场地、动作、对象、原因、时间及变更前后快照；
  - 页面支持筛选、刷新和分页，不开放修改或删除入口。
- 回归：
  - 隔离测试库当前有 47 条真实业务操作日志，其中 46 条带场地、1 条为全局后台操作；
  - 覆盖预约、固定、请假、临时不可排、加班、班次、导出和账号等 27 种动作；
  - 审计前后快照未发现密码、令牌、密钥、OpenID 或会话密钥。
  - 真实 HTTP 执行 6 项审计查询断言：客服本站、客服跨场地拒绝、非法分页拒绝、主播拒绝、管理员全局/分场地和对象类型筛选均通过；
  - 真实后台页面以管理员身份显示 48 条跨场地/全局记录，操作筛选返回 3 条匹配记录，前后快照可展开；
  - 真实后台页面以松江客服身份显示 46 条记录，页面中全部场地列均为“松江”；
  - 页面操作期间浏览器控制台无错误。
- 状态：已修复并通过 API、权限和真实页面回归。

#### QA-AUTO-001：小程序逐页冒烟存在假阳性

- 严重级别：中，测试可靠性缺陷。
- 发现方式：审查微信开发者工具自动化脚本并读取实际渲染文字。
- 原现象：旧脚本依次打开全部角色页面，只要页面存在任意 `view` 就判定通过；“无权访问”、登录失效和接口错误页同样包含 `view`，因此可能被误报为成功。
- 修复：
  - 从首页实际内容识别当前绑定身份；
  - 仅检查该身份有权访问的页面；
  - 等待加载结束，并检查每页关键业务文字；
  - 发现无权访问、凭证、请求失败、服务不可用或加载失败时立即失败；
  - 保留运行时异常监听，结束后返回首页。
- 回归：当前开发者工具化妆师身份的排班、班次、请假、加班和临时不可排班 5 个页面均通过增强后的真实冒烟。
- 状态：已修复并通过真实开发者工具回归。

### 4.7 小程序预约交互与跨端同步

隔离环境中使用主播 `000001` 通过真实小程序控件完成以下闭环：

1. 在预约页面选择目标日期、`阿伟-松江化妆师` 和 `09:00–09:30`，确认后显示“预约成功”；
2. 主播预约查询立即返回新预约，管理员排班看板同时出现同一预约 ID；
3. 从小程序未来七日排班进入改期，把预约调整为 `09:15–09:45`，显示“改期成功”；
4. 原预约保留为 `CANCELLED`，新预约为 `BOOKED`；管理员排班看板移除原预约并显示新预约；
5. 从小程序取消新预约后，预约状态变为 `CANCELLED`，管理员排班看板同步释放档期；
6. 两条历史记录均保留，行版本从 1 正确递增到 2，没有物理删除或重复有效预约。

第一次执行取消控件时，微信开发者工具自动化连接返回 `timeout`，数据库确认没有发生取消；重新连接并重新定位“已预约”卡片后取消成功。该现象属于开发者工具自动化通信抖动，业务接口没有超时、部分提交或重复提交。测试脚本以数据库后置状态为准，不把工具层超时当作业务成功。
