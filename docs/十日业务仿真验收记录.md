# 十日业务仿真验收记录

> 建立日期：2026-07-29
>
> 目的：使用当前准生产人员与账号结构，在隔离数据库中模拟连续十个业务日的真实操作，作为正式部署前的业务验收证据。

## 1. 安全边界

- 仿真数据库从当前准生产数据库复制，测试期间不修改开发库和准生产库。
- 改密码、改主播编号、取消资格、删除账号和删除人员等破坏性操作只发生在隔离数据库。
- 仿真结束后保留结果摘要，不把仿真预约回写到准生产环境。
- 测试专用时间推进只对仿真 API 进程生效，不改变生产业务的未来七日预约规则。

## 2. 数据规模

| 项目 | 目标 |
|---|---:|
| 连续业务日 | 10 日 |
| 每日预约量 | 700–800 笔 |
| 每日基准量 | 750 笔 |
| 每日固定预约 | 约 375 笔 |
| 每日单次预约 | 约 375 笔 |
| 十日预约总量 | 约 7,500 笔 |
| 固定预约占比 | 45%–55% |

每日单次预约同时包含主播本人预约和运营代预约，并穿插取消、改期、档期复用、第二次预约、请假、取消请假、临时不可排班及恢复等操作。

## 3. 角色全流程

### 3.1 账号与身份

- 主播、运营、化妆师和客服使用临时密码登录并完成首次改密。
- 改密后旧密码失效，新密码可以重新登录。
- 管理员重置人员密码后，旧会话失效，人员再次完成首次改密。
- 管理员修改主播编号后，旧编号不能登录，新编号可以登录。
- 删除测试账号后不能继续登录，历史业务记录仍可追溯。

### 3.2 班次与可预约时间

- 客服或管理员设置化妆师初始班次。
- 化妆师申请修改班次，所属场地客服审批。
- 非工作日加班申请、审批及排班生效。
- 化妆师设置局部不可排班后，相应档期不能预约；取消后档期恢复。

### 3.3 固定关系

- 后台直接设置固定关系。
- 运营提交新固定、变更固定、取消固定申请，客服分别执行通过、驳回。
- 固定预约按日期生成且不重复。
- 单日固定取消后释放档期，其他主播可以预约。
- 取消固定后仅结束生效日以后的固定关系，历史排班保留。

### 3.4 每日预约

- 多名主播和运营并发预约不同化妆师与档期。
- 多人抢同一档期只有一人成功。
- 单个主播每天最多两次预约，第二次需要明确确认。
- 预约取消、改期后原记录保留为已取消，新预约占用新档期。
- 取消或请假释放的档期可以被后续预约复用。
- 当天零点后禁止普通角色新增、改期和取消当天预约。

### 3.5 请假与恢复

- 主播请假取消其日期范围内的固定和单次预约。
- 化妆师请假取消其日期范围内的全部预约。
- 化妆师在请假开始前取消请假后，只恢复原有固定预约，不恢复单次预约。
- 请假期间不能产生新的预约冲突。

### 3.6 人员与审计

- 主播预约资格取消和到期恢复。
- 修改主播编号并同步登录名。
- 删除并重新新增测试主播、运营和化妆师。
- 管理员可删除客服；客服不能删除管理员或其他客服。
- 关键操作均写入操作记录，且场地权限隔离有效。

## 4. 数据一致性标准

以下任一非零即判定失败：

- 同一化妆师有效预约时间重叠。
- 同一主播有效预约时间重叠。
- 单个主播单日有效预约超过两次。
- 同一固定规则同一天生成多条预约。
- 已取消预约继续占用档期。
- 请假或不可排班时段内存在未取消预约。
- 跨场地客服审批或修改其他场地数据。
- 删除人员后历史预约、固定申请或操作记录丢失。

## 5. 性能与稳定性标准

- 仿真过程无未处理异常、进程退出或数据库连接耗尽。
- 预约写入成功请求 P95 小于 2 秒。
- 排班看板和可用档期查询 P95 小于 2 秒。
- 预期业务冲突返回 409；不得出现无法解释的 400 或 500。
- 仿真结束后 API、数据库和 Redis 健康检查正常。

项目已有的 600 并发持续压测用于验证峰值读取与抢档期；本次十日仿真重点验证高业务量下的多角色状态流转和数据一致性，两者结论需要共同满足才可进入正式部署。
