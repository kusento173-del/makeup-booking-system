# 文档索引

> 状态：有效
>
> 最后更新：2026-07-21
>
> 目标：让开发者和 Codex 按任务读取最少且充分的上下文，而不是每次通读全部文档。

## 1. 唯一入口

每个开发任务按以下顺序获取上下文：

1. 根目录 `AGENTS.md`：不可违反的开发、质量和 Git 规则。
2. `docs/当前迭代.md`：当前阶段、任务范围和未决事项。
3. 本索引中的“按任务读取”表：选择相关权威文档。
4. 相关代码、测试和最近 Git 记录：确认实际实现状态。

根目录 `README.md` 只负责项目导航，不保存详细业务规则。

## 4. 冲突处理

不同类型的事实由不同文档负责，不建立简单的“整篇文档优先级”：

- 产品范围和用户结果：产品需求文档。
- 精确行为、状态和错误：业务规则与状态流转。
- 授权和数据范围：角色权限矩阵。
- 持久化、事务和并发约束：数据字典与数据库设计。
- 页面表现和操作路径：页面与交互规格。
- 验收证据：测试与验收方案。
- 当前进度：当前迭代。

若两份文档对同一事实描述不一致，不允许静默选择其中一份：先确认预期，更新对应权威文档、关联测试和实现，再创建一个独立 Git 提交。

## 5. 维护规则

- 一条业务事实只在一个权威位置完整定义。
- 其他文档使用链接或章节名引用，不复制大段规则。
- 聊天中的新决定必须落入对应权威文档，聊天记录本身不是项目事实来源。
- 接口文档由 OpenAPI 随代码生成，不提前手工维护第二份接口定义。
- 数据库结构以迁移和 Schema 为执行事实；设计变更同时更新数据库设计文档。
- 过时草稿移入 `docs/archive/`，只有确有归档文件时才创建目录；归档文件不进入默认读取范围。
- `当前迭代.md` 保持简短，每个迭代结束后只保留结论和 Git 版本，详细历史交给 Git。

## 6. 当前完整性结论

九份正式文档已覆盖第一阶段产品、规则、权限、架构、数据库、导入、页面、测试和实施。正式开发过程中只需要随实现补充自动生成的接口文档、数据库迁移、决策记录、部署手册和用户手册，不再为了“看起来完整”提前生成空文档。
